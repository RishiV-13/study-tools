Understand what cloud computing actually is
3h Learn
Watch these three videos — in order, take notes on every one
1
Video 1 (20 min): Search YouTube for NetworkChuck what is cloud computing. He uses relatable analogies and is very beginner-friendly. Pause whenever something is unclear and write it in your notes before continuing.
2
Video 2 (35 min): Search YouTube for John Savill AZ-900 episode 1 cloud computing. He is the best Azure educator on the internet. Take structured notes under these headings: What is cloud, Why use it, Key terms.
3
Video 3 (8 min): Search YouTube for IaaS PaaS SaaS explained simply — watch the Fireship or Simplilearn version. This covers the three cloud service models that come up constantly in both the exam and job interviews.
Study these core concepts until you can explain each without notes
1
What is a data centre? A massive building full of physical servers owned by Microsoft or Amazon. When you 'use the cloud', you are renting computers inside these buildings. Microsoft has data centres in London, Dublin, Amsterdam and many more.
2
What is a region? A geographic area containing one or more data centres. 'UK South' is Azure's London region. Choosing UK South means your data lives in London — important for UK GDPR compliance.
3
What is an availability zone? A separate building within a region. If one building has a power cut, the others stay up. Spreading resources across zones keeps them running — this is 'high availability'.
4
IaaS: You rent raw hardware — VMs, storage, networks. You manage everything on top. Like renting an empty flat and furnishing it yourself.
5
PaaS: You rent a managed platform to run your app on. Microsoft manages the infrastructure. Like renting a furnished flat.
6
SaaS: You use software that lives entirely in the cloud. Microsoft 365 is SaaS. You manage nothing.
7
CapEx vs OpEx: Before cloud, companies bought physical servers (big upfront cost = CapEx). Cloud is OpEx — pay monthly for what you use. This is why companies moved to cloud en masse.
Write a one-page summary in your notes app
1
Write a plain-English summary of everything above as if explaining it to a friend who knows nothing about tech. This is the Feynman method — the most effective learning technique that exists.
2
Include your own definitions for: cloud, region, availability zone, IaaS, PaaS, SaaS, CapEx, OpEx. Use your own words, not copied definitions.
Mastery check — can you answer these without notes?
  • Can you explain the difference between IaaS, PaaS and SaaS with a real-world analogy?
  • If a company says they want their data to stay in the UK for legal reasons, what Azure setting does that relate to?
  • Why did businesses move from buying physical servers to using cloud services?
The Feynman summary is not optional. It is the single most effective study technique for retaining information. Every concept you struggle to explain needs more time before you move on.

Understand Azure's three-level structure
1
Azure organises everything into three levels. You must understand all three — they appear constantly in AZ-104 and in real jobs.
2
Level 1 — Subscription: Your billing account. Think of it like a bank account for Azure spending. Everything you create lives inside a subscription.
3
Level 2 — Resource Group: A container that groups related resources together — like a folder. Key rule: when you delete a resource group, everything inside gets deleted too. This is how you clean up after a project.
4
Level 3 — Resource: The actual thing you created — a VM, a storage account, a network.
5
In the Azure Portal, click 'Resource groups' → '+ Create'. Name it rg-learning-week1, choose 'UK South', click Create. You now have an empty resource group for your first project.
Explore every section of the portal

Use the search bar at the top to search 'Virtual Machine'. This is the fastest navigation method — professionals use it constantly.
3
Click the question mark icon top right and explore the 'Quickstart Center' — it has structured beginner walkthroughs.
4
Click Cloud Shell (terminal icon, top right). This is a browser-based command line connected directly to your Azure account. You won't need it yet, but know it's there.
Write portal notes

Networking fundamentals — the foundation of cloud
3h Learn
Why you're doing this now
1
Networking knowledge underpins everything in cloud. Understanding IP addresses, subnets and ports is essential for AZ-900, mandatory for AZ-104, and tested in every cloud job interview. You already encountered it — RDP runs on port 3389 and you had to open that port. Now you'll understand why.
Watch these videos — take structured notes throughout
1
Video 1 (25 min): Search YouTube for Professor Messer IP addressing explained N10-009. Covers IP addresses, public vs private, IPv4 vs IPv6.
2
Video 2 (20 min): Search YouTube for NetworkChuck subnetting is simple. Subnetting is how you divide a network into sections — the same thing you'll do when building Azure Virtual Networks.
3
Video 3 (15 min): Search YouTube for Professor Messer common ports N10-009. The most important ports: HTTP 80, HTTPS 443, RDP 3389, SSH 22, DNS 53.
Core concepts to master
1
What is an IP address? A unique number identifying a device on a network. Looks like four numbers separated by dots: 192.168.1.50. Every device has one.
2
Public vs private IP: Private IPs are used inside a network (your home Wi-Fi, an Azure VNet) — not reachable from the internet. Public IPs are globally unique and internet-reachable. Your VM had both.
3
What is a subnet? A subdivision of a network. If a network is a block of flats, a subnet is a specific floor. In Azure, you'll create a 'web-servers subnet' and a 'database subnet' to keep things separated and secure.
4
CIDR notation: A way of writing a range of IP addresses. 10.0.0.0/24 means a network starting at 10.0.0.0 with 256 possible addresses. Used constantly when creating Azure Virtual Networks.
5
What is DNS? The internet's phonebook. Translates 'google.com' into an IP address your computer can connect to. Cloud architects configure DNS constantly.
6
What is a port? A number identifying a specific type of traffic on a server. A network security group in Azure is a list of rules allowing or denying traffic based on ports — which is why you had to specifically allow port 3389.
Add a 'Networking concepts' page to your study notes
1
Create a dedicated notes page. Write your own definitions for: IP address, public IP, private IP, subnet, CIDR notation, DNS, port, RDP, SSH, HTTP, HTTPS. Your own words for every single one.
Mastery check — can you answer these without notes?
  • What is CIDR notation and what does /24 mean in plain English?
  • Why did your VM need a public IP address?
  • If you wanted to prevent anyone from connecting to a VM via RDP, what would you do in Azure?
  • What is DNS and why would a cloud architect need to configure it?
Don't try to memorise port numbers by brute force. Use them — every time you create a network security rule in Azure, look up why that port is being used. Context makes numbers stick.

4h Learn

Module: Describe Azure compute and networking services (70 min)
1
Covers Virtual Machines, Azure App Service, Azure Functions, Azure Container Instances, and Azure Virtual Networks. You already have hands-on VM experience, so this will feel grounded.
2
Azure App Service: A PaaS service for hosting web apps. You don't manage the underlying VM — just deploy your code and it runs.
3
Azure Functions: Serverless compute. Small pieces of code that run only when triggered. You only pay for the time it takes to run. No servers to manage.
4
Azure Virtual Networks: This connects directly to your networking study in Task 6. Subnets, CIDR ranges, network security groups — all of it applies here.

Module: Describe Azure storage services (50 min)
1
Covers Azure Blob Storage, Azure Files, Azure Disk Storage, and storage tiers.
2
Blob Storage: Object storage for files of any type — documents, images, video, backups. Massively scalable and very cheap. You'll use this in the Cloud Resume Challenge.
3
Storage tiers: Hot (frequent access), Cool (infrequent), Cold, and Archive (cheapest). Companies save money by automatically moving old data to cheaper tiers. Common exam and interview topic.
4
Redundancy options: LRS keeps 3 copies of data in one data centre. GRS keeps copies in two different regions. Understanding why a company would choose GRS over LRS is architectural thinking you're developing.
Module: Describe Azure identity, access and security (50 min)
1
Identity and access management is a top topic in both exams and interviews.
2
Azure Active Directory (Microsoft Entra ID): Stores user accounts, handles logins, enforces who can access what. Every company using Microsoft 365 already uses it.
3
Azure RBAC: Controls who can do what in Azure. Instead of full admin access, you assign specific roles — like 'Virtual Machine Contributor'. This is the principle of least privilege: give people only the access they actually need.

Complete all sandbox exercises.
